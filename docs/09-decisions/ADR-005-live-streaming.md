# ADR-005: WebRTC Media Streaming via LiveKit SFU

* **Status**: `PROPOSED`
* **Date**: 2026-09-08
* **Deciders**: Architecture Working Group, Media Infrastructure Team

---

## 1. Context & Problem Statement

Classroom lectures and laboratory seminars require low-latency interactive audio, video, and screen sharing:
* Low-latency bidirectional communication (< 300 ms glass-to-glass) to allow spontaneous student questions.
* Support for 100+ concurrent participants in a single stage lecture hall.
* Dynamic network adaptation: Students connecting from weak mobile cellular networks should not degrade the lecture stream for other participants.
* Automated lecture recording to create searchable, chaptered video archives for students who missed class or want to review.
* Must be fully open-source and capable of running self-hosted on institutional hardware without mandatory third-party cloud subscriptions.

---

## 2. Proposed Architectural Decision

We propose selecting **LiveKit** as the core WebRTC Selective Forwarding Unit (SFU) and media pipeline:

1. **Selective Forwarding Unit (SFU)**:
   * Uses a star topology where broadcasters publish audio/video tracks to the SFU once, and the SFU selectively forwards streams to subscribers without transcoding in the critical path.
2. **Simulcast & SVC Support**:
   * Broadcasters publish multiple resolutions (e.g., 1080p, 720p, 360p). The SFU automatically delivers the optimal bitrate stream to each student depending on their current downlink bandwidth.
3. **Stage Role Grants**:
   * Access is secured by LiveKit JWT tokens generated by Spring Boot. Instructors hold `Publisher` privileges; students hold `Subscriber` privileges until granted temporary speaker status via the "Raised Hand" queue.
4. **Automated Recording via LiveKit Egress**:
   * Headless Chromium containers composite speaker video, screen shares, and collaborative whiteboard feeds in real time, encoding an MP4 file and HLS playlist directly to MinIO object storage upon lecture completion.
5. **Cross-Platform Client SDKs**:
   * Official, robust LiveKit SDKs exist for Next.js (WebRTC in browser) and React Native / Expo (iOS and Android).

---

## 3. Consequences

### Positive
* Sub-300ms real-time latency enables natural, interactive classroom conversations.
* Zero external SaaS subscription dependencies; can run air-gapped on campus servers.
* First-class support for automated lecture recording through LiveKit Egress.

### Negative / Challenges
* Self-hosted deployments require opening UDP port ranges (50000–60000) and configuring STUN/TURN for NAT traversal.
* Egress composite recording is CPU-intensive and requires dedicated compute allocation during large recorded lectures.
