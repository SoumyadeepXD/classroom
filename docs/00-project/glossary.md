# Canonical Platform Glossary

This document establishes the official terminology for the **Classroom Platform**. All architectural designs, data models, API endpoints, code identifiers, and documentation must adhere strictly to these definitions.

---

## 1. Domain Entities & Concepts

### Authentication
* **Identity**: The verified representation of a physical human or service account within the system.
* **MFA (Multi-Factor Authentication)**: Second-factor verification via Time-based One-Time Passwords (TOTP) or hardware security keys (WebAuthn).
* **Session**: An authenticated client connection context bounded by access and refresh tokens.
* **SSO (Single Sign-On)**: Federated enterprise authentication via SAML 2.0 or OpenID Connect (OIDC).

### Users
* **User**: Any registered account within the platform.
* **Role**: A system-level or classroom-level permission bundle (e.g., `SUPER_ADMIN`, `INSTITUTION_ADMIN`, `TEACHER`, `TEACHING_ASSISTANT`, `STUDENT`, `GUEST`).
* **Presence**: The real-time activity state of a user (e.g., `ONLINE`, `IDLE`, `IN_CLASS`, `DO_NOT_DISTURB`, `OFFLINE`).

### Institutions
* **Institution**: The top-level multi-tenant organizational entity representing a university, school district, department, or enterprise academy.
* **Academic Term**: A designated time boundary (e.g., Fall 2026, Semester 1) within an institution.
* **Department**: An organizational subdivision of an institution grouping related disciplines.

### Classrooms
* **Classroom**: The primary academic and social container for a course or learning cohort.
* **Section**: A division of a classroom grouping a subset of enrolled students with designated instructors.
* **Syllabus**: The structured curriculum, outline, and schedule attached to a classroom.

### Membership
* **Enrollment**: The association between a user and a classroom with an assigned academic role.
* **Join Code**: An alphanumeric invite key allowing authorized users to self-enroll in a classroom.
* **Approval Queue**: The staging mechanism where prospective members await instructor or admin authorization.

### Channels
* **Channel**: A categorized communication track within a classroom.
* **Channel Category**: A logical grouping of channels (e.g., "Lectures", "General Discussion", "Lab Help").
* **Text Channel**: A persistent real-time chat stream for messages, threads, and attachments.
* **Voice Channel**: An ephemeral audio room where participants can talk, share screens, and collaborate.
* **Announcement Channel**: A broadcast channel where only instructors can publish notices.
* **Live Stage Channel**: A specialized WebRTC lecture hall with structured speaker/listener roles.

### Messaging
* **Message**: A discrete communication unit posted to a text channel.
* **Thread**: A nested side-conversation branching from a parent message to prevent channel clutter.
* **Reaction**: An emoji indicator affixed to a message by participants.
* **Mention**: A targeted notification mechanism directed at a user (`@user`), role (`@teaching-assistants`), or channel (`@everyone`).

### Files
* **File Asset**: A persisted binary object stored in MinIO/S3 and indexed in PostgreSQL.
* **Attachment**: A file asset linked directly to a message, assignment, or submission.
* **Academic Library**: The indexed, persistent repository of reference documents, lecture slides, and recordings in a classroom.

### Assignments
* **Assignment**: A structured learning task published by an instructor requiring student submission.
* **Rubric**: A multi-criteria assessment matrix detailing evaluation dimensions and point allocations.
* **Due Date**: The deadline timestamp after which submissions are marked late or locked.

### Submissions
* **Submission**: The work (files, code, written text) turned in by a student for an assignment.
* **Submission Version**: A snapshot of student work submitted prior to final grading.
* **Plagiarism Score**: The similarity index generated by external plagiarism inspection hooks.

### Grades
* **Grade**: The numerical score and rubric breakdown awarded to a submission.
* **Gradebook**: The institutional matrix tracking all assignment scores across all students in a classroom.
* **Feedback**: Private textual or audio comments provided by instructors to a student regarding their work.

### Live Classes
* **Live Class**: A real-time, WebRTC-powered virtual lecture or seminar session hosted in a stage channel.
* **Stage Speaker**: A participant with broadcast privileges (audio, video, screen share).
* **Raised Hand**: A student request signaling the desire to be granted temporary speaker privileges.
* **Breakout Room**: A transient sub-room spawned from a live class for small-group exercises.

### Recordings
* **Recording**: The captured audiovisual stream of a completed live class session.
* **Transcoding**: The automated processing of raw recordings into adaptive streaming formats (HLS/DASH).
* **Chapter Marker**: A timestamped topic divider within a recorded lecture.

### Notifications
* **Notification**: An asynchronous event alert delivered via push notification, in-app feed, or email.
* **Activity Feed**: A chronological ledger of unread mentions, assignment deadlines, and grade publications.

### Search
* **Search Index**: The full-text indexed catalog spanning messages, course materials, assignments, and transcripts.

### Moderation
* **Moderation Action**: An intervention (mute, kick, message deletion, warning) taken by an instructor or administrator.
* **Audit Log**: An immutable chronological record of administrative and moderation actions.

### Administration
* **Tenant Governance**: Platform configuration spanning institutional branding, feature flags, and storage limits.

### Security
* **RBAC**: Role-Based Access Control enforcing coarse-grained permission checks.
* **ABAC**: Attribute-Based Access Control enforcing fine-grained contextual checks (e.g., student can only view their own submission).

### Deployment
* **Self-Hosted**: An installation running on infrastructure controlled and owned by the institution.
* **Cloud-Managed**: An installation running on multi-tenant cloud infrastructure managed centrally.
